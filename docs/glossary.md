# Глоссарий предметной области

Единый язык проекта. Термины отсюда используются одинаково в модели Event Storming,
в README, в `.proto` и в коде.

Сдаваемый артефакт четырёх работ: ПР1 — сформировать, ПР2, ПР3 и ПР4 — обновить.

Правило: если термина здесь нет, его нельзя вводить в код молча. Сначала строка
в таблице, потом идентификатор.

---

## Спорные пары

Термины, которые уже начали расходиться. Решения зафиксированы, дальше только так.

### Запись и визит

**Запись** — единственное официальное название сущности. Договорённость клиента с
специалистом о времени и услуге. Существует с момента создания и до отмены или завершения.
В коде — `Appointment`.

**Визит** — разговорный синоним завершённой записи (`APPOINTMENT_STATUS_COMPLETED`).
Допустим в устной речи и в интерфейсе для пользователя. **В коде не употребляется.**

Разница существенная: запись может не состояться, визит — состоявшийся факт. Отчёт
«записей за месяц» и «визитов за месяц» дают разные числа, и путать их нельзя.

### Услуга и сервис

**Услуга** — то, что салон оказывает клиенту: стрижка, окрашивание, маникюр.
В коде — `mirea.catalog.v1.Service`.

**Сервис** — микросервис, элемент архитектуры. Только в инфраструктурном смысле.

В русском тексте они омонимы, в коде их разводит пакет: `catalog.Service` — услуга,
`CatalogService` — микросервис. В прозе услугу сервисом не называем никогда.

### Сотрудник и специалист

**Сотрудник** — любой работник филиала: `Employee`, роли `admin`, `manager`, `specialist`.

**Специалист** — частный случай: сотрудник с ролью `specialist`, который оказывает услуги.
Только специалиста появляются в расписании и в записях.

Не взаимозаменяемы: администратор филиала — сотрудник, но не специалист, и записать
клиента к нему нельзя.

### Филиал и салон

**Филиал** — точка сети, единица учёта: `Branch`. Владеет своим складом, прайсом
и расписанием.

**Салон** — разговорное название филиала. В коде как обозначение филиала
не употребляется.

Исключение: `mirea` в пространстве имён (`mirea.catalog.v1`, `mirea.events`,
проект `mirea-crm`) — это название продукта целиком, а не филиал. Коллизии нет,
но на защите вопрос вероятен.

## Ограниченные контексты (ПР3)

| Контекст | Отвечает за | Сервис |
|---|---|---|
| Организация | Компании, филиалы, сотрудники, графики работы | `core-service` |
| Клиенты | Карточки клиентов, контакты, лояльность | `client-service` |
| Записи | Запись к специалисту, расписание, занятость слотов | `booking-service` |
| Каталог | Услуги, цены, нормативы расхода материалов | `catalog-service` |
| Склад | Остатки расходников, списание, пополнение | `inventory-service` |
| Расчёты | Счета, оплаты, комиссия специалиста | `billing-service` |
| Уведомления | Напоминания клиентам, алерты администраторам | `notification-service` |
| Аналитика | Выручка, загрузка специалистов, конверсия | `analytics-service` |

## Агрегаты (ПР3)

| Агрегат | Корень | Входит в состав | Контекст |
|---|---|---|---|
| Компания | `Company` | — | Организация |
| Филиал | `Branch` | — | Организация |
| Сотрудник | `Employee` | Смены (`WorkShift`) | Организация |
| Клиент | `Client` | Баланс баллов | Клиенты |
| Запись | `Appointment` | — | Записи |
| Услуга | `Service` | Нормативы расхода (`ConsumptionNorm`) | Каталог |
| Складская позиция | `StockItem` | Движения по складу | Склад |
| Счёт | `Invoice` | Позиции счёта | Расчёты |

Ссылки между агрегатами — только по идентификатору. Смена не существует отдельно от
сотрудника, норматив — отдельно от услуги.

## Термины предметной области

| Термин | Определение | В коде |
|---|---|---|
| Компания | Юридическое лицо, владеющее сетью филиалов | `Company` |
| Филиал | Точка сети со своим складом, прайсом и расписанием | `Branch` |
| Сотрудник | Работник филиала в одной из трёх ролей | `Employee` |
| Специалист | Сотрудник с ролью `specialist`, оказывает услуги | `EMPLOYEE_ROLE_SPECIALIST` |
| Администратор филиала | Сотрудник с ролью `manager`, ведёт записи и склад | `EMPLOYEE_ROLE_MANAGER` |
| Владелец сети | Роль `admin`, полный доступ ко всем филиалам | `EMPLOYEE_ROLE_ADMIN` |
| Смена | Отрезок рабочего времени специалиста | `WorkShift` |
| График | Набор смен специалиста за период | `GetEmployeeSchedule` |
| Клиент | Посетитель салона | `Client` |
| Запись | Договорённость клиента с специалистом о времени и услуге | `Appointment` |
| Слот | Отрезок времени в расписании специалиста | — |
| Услуга | Процедура из прайса: длительность, цена, норматив расхода | `Service` |
| Прайс филиала | Цены услуг конкретного филиала | `GetService(branch_id)` |
| Расходник | Материал, списываемый при оказании услуги | `Consumable` |
| Норматив расхода | Сколько расходника уходит на одну процедуру | `ConsumptionNorm` |
| Остаток | Количество расходника на складе филиала | `StockItem` |
| Минимальный порог | Остаток, ниже которого поднимается тревога | `threshold` |
| Списание | Уменьшение остатка по факту оказанной услуги | `ConsumablesWrittenOff` |
| Счёт | Документ на оплату завершённой записи | `Invoice` |
| Комиссия специалиста | Доля специалиста от оплаченного счёта | `employee_commission` |
| Баллы лояльности | Бонусы, начисляемые клиенту от суммы оплаты | `AddLoyaltyPoints` |

## Доменные события (ПР1)

Глагол в прошедшем времени: событие уже произошло и отменить его нельзя.

| Событие | Что произошло | Ключ маршрутизации |
|---|---|---|
| Филиал открыт | Заведён новый филиал | `branch.opened` |
| Сотрудник принят | Сотрудник добавлен в штат филиала | `employee.hired` |
| Клиент зарегистрирован | Заведена карточка клиента | `client.registered` |
| Запись создана | Клиент записан к специалисту | `appointment.created` |
| Запись отменена | Запись снята до начала | `appointment.cancelled` |
| Запись завершена | Специалист закрыл визит | `appointment.completed` |
| Расходники списаны | Материалы списаны по нормативу | `consumables.written_off` |
| Остаток на исходе | Остаток упал ниже порога | `stock.low` |
| Счёт выставлен | Сформирован документ на оплату | `invoice.issued` |
| Счёт оплачен | Оплата зафиксирована | `invoice.paid` |

## Команды и действующие лица (ПР2)

| Действующее лицо | Кто это |
|---|---|
| Владелец сети | Управляет компанией и филиалами |
| Администратор филиала | Ведёт записи, клиентов и склад одной точки |
| Специалист | Оказывает услуги, закрывает свои визиты |
| Клиент | Записывается, приходит, платит |
| Система | Плановые действия без участия человека: напоминания, списания |

| Команда | Кто вызывает | Чем заканчивается |
|---|---|---|
| Зарегистрировать компанию | Владелец сети | Компания создана |
| Открыть филиал | Владелец сети | Филиал открыт |
| Принять сотрудника | Владелец сети | Сотрудник принят |
| Завести клиента | Администратор филиала | Клиент зарегистрирован |
| Записать клиента | Администратор филиала, клиент | Запись создана |
| Отменить запись | Администратор филиала, клиент | Запись отменена |
| Завершить запись | Специалист | Запись завершена |
| Завести услугу | Владелец сети | — |
| Изменить цену | Владелец сети | — |
| Пополнить склад | Администратор филиала | — |
| Списать расходники | Система | Расходники списаны, возможно остаток на исходе |
| Выставить счёт | Система | Счёт выставлен |
| Отметить оплату | Администратор филиала | Счёт оплачен |
| Начислить баллы | Система | — |
| Отправить уведомление | Система | — |

### Бизнес-правила

- Записать клиента можно только к специалисту, у которого на это время есть смена.
- Один специалист не может иметь двух записей на пересекающееся время.
- Смены одного сотрудника не пересекаются.
- Услуга доступна к записи только в том филиале, где она есть в прайсе.
- Списание расходников происходит только по завершённой записи, не по созданной.
- Счёт выставляется на цену, зафиксированную в момент записи, а не текущую.
- Баллы начисляются только после оплаты счёта и ровно один раз.
- Специалист видит и закрывает только свои записи, комиссию — только свою.

## Термины взаимодействия (ПР4)

| Термин | Значение |
|---|---|
| Синхронное взаимодействие | Вызывающий ждёт ответа. У нас — gRPC между сервисами |
| Асинхронное взаимодействие | Отправил и продолжил работу. У нас — RabbitMQ и NATS |
| Доменное событие | Факт, который нельзя потерять. RabbitMQ, durable-очереди |
| Эфемерное сообщение | Обновление, устаревающее за секунды. NATS, без гарантий |
| Север-юг | Трафик снаружи внутрь: клиент → шлюз → сервис, HTTP |
| Восток-запад | Трафик между сервисами, только gRPC |
| Контракт | Описание границы сервиса в `proto/`, источник правды |
| Тонкое событие | Событие с идентификаторами; детали потребитель запрашивает сам |
